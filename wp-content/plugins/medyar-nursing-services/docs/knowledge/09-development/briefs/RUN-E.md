## ۱. مشکل اصلی (باگ B-D.1)
وقتی بیمار واقعی (نه ادمین/پیش‌نمایش) وارد می‌شود، صفحات «جزئیات سفارش» و «داشبورد» هنوز از fixture می‌خوانند: نام ساختگی («حسن محمدی»)، «پرستار شما مشخص شد»، دکمهٔ «لغو» روی سفارشِ لغوشده. این یعنی **جایگزینی fixture برای کاربر واقعی ناتمام است** (T-3.9). قاعدهٔ نهایی:
- **کاربر واقعی** = لاگین‌شده، `! current_user_can('manage_options')` و دارای `MNS_Roles::CAP_PATIENT_PANEL` (بیمار) یا نقش `mns_nurse` تأییدشده (پرستار): **همیشه داده از API/سرویس** (حتی اگر `uiStatic=1`)، و هرگز fixture نبیند؛ ناموجود ⇒ حالت خالی/۴۰۴ فارسی.
- **ادمین/پیش‌نمایش** (`MNS_Dev::enabled()` یا ادمین): رفتار قبلی (fixture + `?mns_case`) بدون تغییر.
یک helper مشترک بساز، مثلاً `MNS_Nurse_Access::is_real_panel_user( string $panel ): bool`، و **همه** viewها از همان استفاده کنند (نه شرط‌های پراکنده).

## ۲. کارت‌ها

**T-E.1 — جزئیات سفارش بیمار (واقعی).**
`page-order-view.php`: برای کاربر واقعی `$d` (ساختار همان‌ی که قالب می‌خواهد: status, service, patient, when, nurse, fields…) را از `MNS_Patient_Orders_Api::get_for()` بساز؛ نگاشت وضعیت‌ها به ۵ مرحلهٔ ردیابی؛ نام پرستار فقط وقتی تخصیص خورده؛ `can_cancel` از سرور (دکمهٔ لغو فقط وقتی مجاز)؛ کد نامعتبر/غیرمالک ⇒ همان صفحهٔ «این صفحه پیدا نشد» (۴۰۴ نرم)؛ هیچ داده‌ٔ fixture در HTML نباشد. **ساختار/CSS بدون تغییر.** دکمهٔ لغو واقعاً به `POST /orders/{code}/cancel` (با `?_envelope=1`) وصل باشد و بعد از موفقیت صفحه را تازه کند (پیام خطای فارسی برای `ERR_BAD_STATE`).

**T-E.2 — داشبورد بیمار (واقعی).**
`page-dashboard.php`: سفارش فعال/بعدی، تعداد سفارش‌ها، دکمهٔ «ثبت سفارش جدید»؛ همه از دیتابیس؛ حالت خالی برای بیمار بدون سفارش.

**T-E.3 — فهرست سفارش‌های بیمار و پرستار (واقعی، سبک).**
`page-orders.php` (بیمار) برای کاربر واقعی فقط از `list_for` بخواند و فیلدهایی که قالب لازم دارد (`patient_id`, نام بیمار، `when`, وضعیت، پرستار) را از API تأمین کن؛ تعداد محدود (۵۰) و DOM سبک (B-D.5: صفحه با DOM fixture مرورگر را می‌کُشت). همین را برای پرستار بررسی کن: `page-orders.php`, `page-dashboard.php`, `page-order-view.php` (پرستار) برای کاربر واقعی از `MNS_Nurse_Orders_Api` — اگر هنوز fixture می‌خوانند وصل کن؛ نشانی/تلفن فقط در `assigned/in_progress`، هیچ کد ملی/مبلغ.

**T-E.4 — صفحات M4+ (هنوز بدون بک‌اند) برای کاربر واقعی.**
طبق D-5: صفحاتی که بک‌اندشان هنوز نیست (checklist/report/drug/ratings پرستار؛ invoices/loyalty/recurring/surveys بیمار، و هرچه fixture است) برای **کاربر واقعی** نباید داده‌ٔ ساختگی نشان دهند؛ نوار/صفحهٔ روشن «این بخش به‌زودی فعال می‌شود» (همان کامپوننت‌های UI موجود؛ بدون CSS جدید جز در صورت ضرورت) نشان بده و لینک‌های ناوبری به آن‌ها آسیبی نزند. برای ادمین/پیش‌نمایش همه‌چیز مثل قبل. **`public/views/nurse/page-ratings.php` را دست نزن** (کار ناتمام دیگری).

**T-E.5 — E2E: سناریوی «سفارش تخصیص‌یافته».**
در ابزار E2E (`class-mns-e2e.php` + `class-mns-admin-e2e.php`) یک دکمهٔ جدید «ساخت سفارش نمونهٔ تخصیص‌یافته» اضافه کن (همان قیدهای امنیتی: فقط وقتی فعال؛ فقط کاربران `mns_e2e_*`؛ فقط روی `develop.`): با سرویس‌های واقعی (`MNS_Orders`/`MNS_Order_Machine::transition`) برای `mns_e2e_patient` یک سفارش سرم فردا ۸–۱۲ منطقهٔ ۱۰ ساخته و به `mns_e2e_nurse_f` تخصیص دهد (`assigned`)، و یک سفارش دوم برای مرد/منطقهٔ ۱ و `mns_e2e_nurse_m`. سفارش‌ها در پاک‌سازی E2E حذف شوند (بررسی کن). `fake_national_id()` را برای seed دوباره‌اجراشونده درست نگه دار (بروزرسانی ردیف‌های قبلی).

**T-E.6 — تست مرورگر مجدد (فقط آنچه در RUN-D ناقص ماند).**
بعد از آماده‌شدن T-E.1…T-E.5 و آپلود، گزارش `reports/T-E.5.md` را بنویس و **تا ظهور `.e2e/links.json` تازه منتظر بمان** (ناظر آن را بعد از «ساخت دادهٔ E2E + ساخت سفارش نمونه» می‌سازد؛ هر ۳۰ ثانیه چک؛ حداکثر ۳۰ دقیقه). سپس:
1. بیمار: داشبورد ⇒ سفارش فعال واقعی؛ فهرست سفارش‌ها ⇒ سفارش‌ها (بدون کرش مرورگر)؛ جزئیات سفارش تخصیص‌یافته ⇒ نام پرستار واقعی، مراحل درست، «لغو» مجاز؛ لغو از UI ⇒ صفحه «لغو شده» و دکمه حذف؛ بیمار دیگر/کد دیگر ⇒ «پیدا نشد». **در هیچ‌کدام نباید متن fixture («حسن محمدی» و…) دیده شود** (با جستجوی متن در DOM بررسی کن).
2. پرستار زن: فهرست ⇒ سفارش تخصیص‌یافته؛ جزئیات ⇒ نشانی/تلفن؛ **خاموش‌کردن همان روز/بازه در «برنامه و دسترسی» ⇒ پیام `ERR_SLOT_HAS_ORDER`**؛ حذف منطقهٔ سفارش ⇒ هشدار تعداد؛ باز کردن فایل نسخه (اگر سفارش نسخه دارد) ✓؛ بعد از لغو ✗.
3. پرستار مرد: سفارش مرد منطقهٔ ۱ ⇒ می‌بیند؛ سفارش پرستار زن ⇒ ۴۰۴.
4. صفحات M4+ برای هر دو ⇒ نوار «به‌زودی»، بدون داده ساختگی.
5. موبایل ۳۷۵px برای جزئیات سفارش و داشبورد ⇒ بدون اسکرول افقی.
برای هر مرحله کنسول مرورگر را بخوان. هر URL پنل را با `&_=<timestamp>` باز کن (کش CDN، B-D.2). اگر مرورگر خودکار روی صفحه‌ای کرش کرد، همان‌جا با `get_page_text`/REST ادامه بده و بنویس.
