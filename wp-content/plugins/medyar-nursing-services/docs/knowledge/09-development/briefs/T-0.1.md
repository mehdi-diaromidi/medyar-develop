2. `wp-content/plugins/medyar-nursing-services/docs/knowledge/09-development/README.md` و `07-roadmap.md` (فقط بخش M0) و `09-supervision-playbook.md` (§۳، §۴، §۸)
3. rule فعال `.cursor/rules/mns-backend.mdc` (قوانین سخت)

## ۱. هدف
وقتی کد بک‌اند جدید (که در کارت‌های بعدی نوشته می‌شود) خطای نحوی یا استثنا داشته باشد، **سایت develop سفید نشود**؛ پنل‌های استاتیک فعلی کار کنند، خطا ثبت شود و در wp-admin به ادمین اعلان داده شود. (PHP روی ماشین نیست؛ lint محلی نداریم و هر تست روی سایت واقعی انجام می‌شود، پس این محافظ حیاتی است.)

## ۲. وضعیت فعلی کد (لازم نیست دنبالش بگردی)
- `medyar-nursing-services.php`: ثابت‌ها (`MNS_VERSION`, `MNS_DB_VERSION`, `MNS_PLUGIN_DIR`…)، `require` autoloader، hookهای activation، و در `plugins_loaded`: `MNS_Plugin::instance()->init()`.
- `includes/class-mns-plugin.php`: `init()` این‌ها را اجرا می‌کند: `MNS_Activator::maybe_upgrade()` ← `MNS_Roles::register()` ← `load_textdomain` ← (در admin) `MNS_Admin::instance()->init()` ← `MNS_Public::instance()->init()` ← `MNS_Assets::init()` ← `MNS_Rewrite::instance()->init()`.
- `includes/class-mns-autoloader.php`: فقط یک **نقشهٔ دستی** `کلاس => مسیر` و `spl_autoload_register`.
- هیچ جدول/AJAX/REST واقعی نیست؛ صفحات از fixture می‌خوانند و **نباید تغییر رفتار بدهند**.

## ۳. تحویل‌ها

### ۳.۱ کلاس `MNS_Backend` — فایل جدید `includes/class-mns-backend.php`
- `MNS_Backend::boot()` (static) از `MNS_Plugin::init()` **در انتها** صدا زده شود (بعد از همهٔ کدهای فعلی؛ داخل خود `boot` همه‌چیز در `try/catch (\Throwable)` باشد تا حتی خود محافظ هم سایت را نبرد).
- **فهرست ماژول‌ها:** `private static function modules(): array` یک آرایه از توصیف‌گرها برمی‌گرداند: `array( 'slug' => 'core', 'file' => 'includes/backend/class-mns-backend-core.php', 'class' => 'MNS_Backend_Core' )`. فعلاً **فقط یک ماژول نمونهٔ خالی `core`** تعریف کن (کلاس `MNS_Backend_Core` با متد static `boot()` که هیچ کاری نمی‌کند) تا مکانیزم قابل‌تست باشد. کارت‌های بعدی ماژول اضافه می‌کنند.
- برای هر ماژول: `require_once MNS_PLUGIN_DIR . $file` داخل `try { } catch ( \Throwable $e )`، سپس `$class::boot()` داخل `try/catch` جدا. استثنای `ParseError` از `require` در PHP 7+ گرفتنی است؛ **حتماً `\Throwable` بگیر نه `Exception`**.
- شکست یک ماژول، ماژول‌های دیگر و سایت را متوقف نمی‌کند.
- متدهای عمومی: `MNS_Backend::is_active(): bool`، `MNS_Backend::module_ok( string $slug ): bool`، `MNS_Backend::errors(): array`.

### ۳.۲ kill-switch
- ثابت `MNS_BACKEND_DISABLED` (اگر `true` تعریف شده، `boot()` هیچ ماژولی را بارگذاری نمی‌کند) **یا** option `mns_backend_disabled` (truthy) همان اثر را دارد. `is_active()` هر دو را در نظر می‌گیرد.
- روی ادمین (کاربر با `manage_options`) یک اعلان info وقتی غیرفعال است: «بک‌اند MNS غیرفعال است».

### ۳.۳ ثبت خطا و اعلان ادمین
- هنگام شکست ماژول: رکورد `array( 'module' => slug, 'message' => ..., 'file' => basename..., 'line' => ..., 'type' => get_class($e), 'time' => time() )` در option `mns_backend_errors` (حداکثر ۲۰ رکورد آخر؛ با `autoload=false`). **فقط وقتی رکورد جدید/متفاوت است بنویس** تا هر درخواست دیتابیس را ننویسد (مثلاً کلید `md5(slug.message.file.line)` و حداقل ۱ ساعت فاصله). علاوه بر آن `error_log( '[MNS] ...' )`.
- اعلان `notice-error` در wp-admin (فقط `manage_options`) با فهرست خطاها (ماژول، پیام کوتاه، `file:line`، زمان) و دکمهٔ «پاک‌کردن» (`admin_post_mns_backend_clear_errors` + nonce + `current_user_can('manage_options')`، سپس `wp_safe_redirect` به `wp_get_referer()`). **همهٔ خروجی‌ها escape شوند.** پیام خطا ممکن است مسیر فایل سرور را لو دهد؛ فقط `basename` نمایش بده.

### ۳.۴ autoloader
- `MNS_Autoloader::load()` را گسترش بده: اگر کلاس در نقشهٔ دستی نبود، **فالبک**: نام `MNS_Foo_Bar` ⇒ فایل `class-mns-foo-bar.php` را به‌ترتیب در این پوشه‌ها بگرد: `includes/`, `includes/backend/`, `includes/db/`, `includes/domain/`, `includes/services/`, `includes/rest/`, `admin/`, `admin/list-tables/`, `public/`. اگر نبود هیچ خطایی نده و برگرد.
- رفتار نقشهٔ دستی فعلی بدون تغییر بماند. کلاس‌های `MNS_Backend`/`MNS_Backend_Core` در نقشهٔ دستی هم ثبت شوند (برای سرعت و وضوح).

### ۳.۵ ابزار تست خرابی عمدی (برای تأیید AC)
- فایل `includes/backend/_selftest/broken-syntax.php` با **خطای نحوی عمدی** (بعد از یک کامنت توضیحی که می‌گوید «عمداً خراب؛ فقط وقتی با ?mns_selftest_broken لود می‌شود»؛ مثلاً یک `function (` ناتمام).
- ماژول تستی `selftest_broken` فقط وقتی به لیست ماژول‌ها اضافه شود که: کاربر لاگین‌شده با `manage_options` باشد **و** `$_GET['mns_selftest_broken']` برابر `'1'` باشد. آن ماژول `require_once` فایل خراب را انجام می‌دهد؛ باید `ParseError` گرفته و ثبت شود. در حالت عادی این فایل **هرگز** include نمی‌شود.

## ۴. فایل‌های مجاز
`medyar-nursing-services.php` (فقط اگر لازم شد؛ ترجیحاً تغییر نکند)، `includes/class-mns-plugin.php` (فقط افزودن فراخوانی `MNS_Backend::boot()` در انتهای `init()`)، `includes/class-mns-autoloader.php`، `includes/class-mns-backend.php` (جدید)، `includes/backend/class-mns-backend-core.php` (جدید)، `includes/backend/_selftest/broken-syntax.php` (جدید)، `includes/backend/index.php` و `includes/backend/_selftest/index.php` (جدید؛ مثل بقیه: فقط `<?php // Silence is golden.`).
**هیچ فایل دیگری را تغییر نده** (viewها، CSS/JS، fixtureها، قالب، پلاگین‌های دیگر).

## ۵. ممنوع
`@` برای سرکوب خطا · `eval` · `die()/exit` وسط منطق · نوشتن در دیتابیس به‌جز option `mns_backend_errors`/`mns_backend_disabled` · هر `$wpdb` · ویژگی PHP > 8.0 · تغییر رفتار صفحات فعلی · `deploy`/FTP · commit/push.

## ۶. معیار پذیرش (AC-M0-1) — ناظر این‌ها را روی develop بررسی می‌کند
1. بدون هیچ تغییری: صفحهٔ سایت، `/wp-admin/`، `/nursing-nurse-panel/?mns_panel=nurse&mns_page=dashboard` و `/nursing-patient-panel/?mns_panel=patient&mns_page=dashboard` بدون هیچ خطا و دقیقاً مثل قبل بالا می‌آیند.
2. با `…/wp-admin/?mns_selftest_broken=1` (ادمین): HTTP 200، wp-admin کامل بالا می‌آید، اعلان قرمز «ماژول selftest_broken … ParseError … broken-syntax.php:N» دیده می‌شود، و پنل‌های استاتیک پرستار/بیمار همچنان سالم‌اند.
3. دکمهٔ «پاک‌کردن» اعلان را حذف می‌کند (با nonce؛ بدون nonce ⇒ `wp_die`).
4. با `define('MNS_BACKEND_DISABLED', true)` ماژولی لود نمی‌شود و اعلان info دیده می‌شود.
5. بازبینی ناظر روی diff: تعادل `{}`، `\Throwable`، escape خروجی، nonce/cap، نبود `@`/`eval`، فقط فایل‌های مجاز تغییر کرده.

## ۷. چک خودت قبل از تحویل (چون PHP نداری، فایل‌ها را یک‌بار خط‌به‌خط بخوان)
تعادل `{ } ( ) [ ]` · هر دستور با `;` · کاما در آرایه‌ها · `<?php` ابتدای هر فایل · `if ( ! defined( 'ABSPATH' ) ) { exit; }` · بدون `?>` انتهایی در فایل‌های کلاس · نام فایل با نام کلاس هم‌خوان · `MNS_PLUGIN_DIR` درست استفاده شده · فقط ویژگی‌های PHP 8.0.
